## 2. Concrete types (`src/engine/evaluate.ts`)

```ts
/** The four evaluation outcomes for a constraint body. */
export type EvaluationResult =
  | "satisfied"
  | "violated"
  | "indeterminate"
  | "error";

export interface EvalContext {
  resolveRef: (name: string) => number[] | null;
  //  - null  => binding not declared  -> error
  //  - []    => no numeric data yet    -> indeterminate
  //  - [...] => concrete values        -> fed to arithmetic/aggregation
}
```

The AST node type `ExpressionNode` is unchanged from M0 (`src/model/types.ts`):

```ts
export interface ExpressionNode {
  op: string;                                  // whitelisted operator (D09)
  args: Array<ExpressionNode | { ref: string } | number>;
}
```

## 3. Operator whitelist (D09) — closed set

- Arithmetic: `+ - * /`  (arity 2, number; `/` by 0 → error)
- Comparison: `< <= > >= == !=`  (arity 2, number → boolean)
- Logical: `and or` (arity 2, boolean), `not` (arity 1, boolean)
- Aggregation: `sum avg min max count`  (arity 1, exactly one `{ref}`)

Anything else → `error`. Top-level MUST be boolean; bare numeric body → `error`.

## 4. Engine internals (mechanics)

- `evaluate(expr, ctx)` enters `evalBool` (boolean layer).
- Boolean layer handles `not` / `and` / `or` / comparison; everything else at
  the top level is `error`.
- Numeric layer (`evalNum`) handles aggregation and arithmetic; bare `{ref}` is
  `error` outside aggregation.
- Internal `NumResult = {value} | {indeterminate} | {error}` lets missing data
  and bugs flow cleanly through the recursion.
- Propagation: `indeterminate` or `error` in any child short-circuits the parent
  (indeterminate stays indeterminate; error dominates).

## 5. Store wiring (`MemoryGraph.evaluateConstraint`)

```ts
evaluateConstraint(id: string): EvaluationResult
```

- throws `ModelError` if constraint absent;
- returns `error` if `expression` is undefined;
- `resolveRef(name)`:
  - `null` if `name` not in `constraint.bindings`;
  - otherwise scans all `core:statement` nodes with
    `dimension_id === bindings[name]`, keeps `number` values, returns them
    (`[]` when none → indeterminate).

**Scope note:** M1 aggregates over **all** statements of a dimension regardless
of `state`. State-aware aggregation (count only `accepted`, etc.) is deferred.
