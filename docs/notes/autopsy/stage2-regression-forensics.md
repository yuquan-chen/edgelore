# 阶段 2 回归取证 + 新库漂移审计

> 2026-09-19 · 双 agent 并行取证（回归配对 + 漂移/预算审计），全程本地只读
> 背景：阶段 1→2 同一组 100 题，总分 38→53，但多会话 32→16（-16pp）、知识更新 64→50（-14pp）

## 一、回归题取证（stage1 对 → stage2 错，共 12 题，11 题详查）

| 失败模式 | 占比 | 案例 |
|---|---|---|
| **(a) 金料在库但散在多个 key**（漂移散账） | **7/11 (64%)** | 瑜伽频率拆 3 个 key、鱼缸拆 4+ key、Apex 等级拆 2 key（且 17 个 apex 系 key 竞争 k 预算只进 1 个） |
| **(b) 新抽取净丢数字** | **3/11 (27%)** | $50 停车罚单、"three meals"、6:00 pm——**旧库都有完整 accepted 语句，新抽取把量词/时间剥掉了** |
| (c) key 干净但检索没取到 | 1/11 (9%) | 播放量两数字干净在库，词面排名 4200+ 位 |

知识更新的"最新 accepted 覆盖旧值"语义**跨 key 直接失效**（3 例全中：同一语义槽多个 key 各持一个 accepted 值）。

## 二、新库漂移审计（vs 旧库备份）

| 指标 | 新库 | 旧库 |
|---|---|---|
| 维度 / distinct key | 5657 / 5657（**key 零复用**） | 4612 / 4429 |
| 漂移指数（严格口径） | 0.79 对/key | 0.56（**恶化 1.40x**） |
| 最大相似连通分量 | **1070 key（19% 的 key 空间）** | 90 key（2%） |
| tentative 占比 | 60%（assistant 署名语句） | 15% |
| >20 语句巨型 key | 14 个（recommendedStrategies 单 key 273 条） | 2 个 |

**新失败形态**：`recommend*` / `userX*` 泛化 catch-all key 把异质内容吸进巨型维度——反漂移三层（knownDimensions/similarDimensions/prompt 规则）在新库实测零复用。

## 三、词面 attractor 问题（意外发现，独立于漂移）

词面 containment 打分偏向长 value：8 个巨型语句（如 736 字符的 38 部电影列表，来自 ultrachat/sharegpt 噪声会话）以 0.21-0.35 分**霸占每次查询的全部 8 个检索槽**——与 query 无关的全局 attractor；金证据语句最好名次 #594/8402。
**分组预算不是瓶颈**：k=8 时平均只渲染 26.5 行，48 行上限从未触发；瓶颈在 k=8 屏幕本身被 attractor 占满 + 金证据散在 19.6 个 key/组（0/20 组能进上下文）。

## 四、修复优先级（数据排序）

1. **词面打分归一化**（F1 式平衡：query 覆盖率 × doc 精确率）——几行代码，直接解除 attractor 霸占
2. **M5 维度别名合并**——从 P2 提升为最高优先工作流（64% 的回归都指向它）；100 题取证里的 7 个散账案例就是现成的验收用例
3. **抽取 prompt 补"不得剥量词/时间"**——一行措辞，但要随下次重摄入批量生效
4. 裁决台 576 个 conflict + 60% tentative：产品侧治理材料，非 benchmark 阻塞
