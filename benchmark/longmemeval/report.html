错误归因（全量 95 个错误回答 + 235 个不当拒答）

发现 1 · 拒答危机（235 题）
52.8% 的题目回答了"不知道"，其中 235 题的金标准其实有答案。原因：检索没有召回足够的记忆 + 回答 prompt 的拒答门槛太保守。
→ 修法 提高检索召回率（增加 k 值）+ 调优回答 prompt 的拒答阈值
发现 2 · AI 回复丢失（49 题拒答）
抽取 prompt 明确写了"the assistant only helps"——AI 自身的有价值结论（推荐、总结、判断）被系统性丢弃。单会话助手能力 7.1% 是直接后果。
→ 修法 去掉抽取偏向，同时评估 user 和 assistant 的对话内容
发现 3 · 计数不全（~20 题）
"参加了几场婚礼？"金标准 3 场，我们答 1 场。原因：superseded 的记忆被检索排除 → 历史计数必然偏少。这是"标而不裁"治理机制的已知副作用。
→ 修法 回答层区分"当前状态查询"（只看 accepted）和"历史计数查询"（含 superseded）
发现 4 · 维度漂移（全局影响）
同一概念被存为 owner / manager / projectLeader 等不同维度 key → 检索时只命中其中一个 → 另外的记忆被漏掉。4016 个维度中大量是同一概念的变体。
→ 修法 维度别名表 + 后台合并（M5 生命周期设计已规划）

✓ 成功模式（164 题答对的分析）

冲突治理有效：知识更新 62.5%——事实变更后正确引用了新值，不引用被 superseded 的旧值。这是我们"标而不裁"机制在基准上的直接验证。
拒答设计有效：76.7% 拒答准确率——记忆不够就诚实说"不知道"，不编造。ask 层的拒答规则工作正常。
基础事实召回正常：单会话用户 67.2%——"学历是什么""用什么洗发水"这类简单事实的存取没有问题。
